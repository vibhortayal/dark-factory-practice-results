## Blocking finding F1 (from the Verifier)

The service cannot import its own export once it is larger than 8 MiB (stage-1 §10: "It must accept an unchanged export produced by this service"; rows X2/X3 through B3.1, and UP3).
- Fixture of two users plus N seeded payments and N seeded requests, all accepted by reset with 204: N = 10000 → export 5.35 MB, import 204; N = 14000 → export 7.52 MB, import 204; N = 20000 (fixture only 4.6 MB) → export 10.77 MB, import into a second container and into the same container both fail with a broken connection; expected 204.
- Cause: `MAX_BODY = 8 * 1024 * 1024` (app.py:33) applied to every request body, including `POST /_test/import`. The stage-3 export carries revisions and statement snapshots, about 390 bytes per payment; every first `GET /statement` adds a snapshot to the export, so reads alone can push a smaller state over. Reset fixtures above 8 MiB are refused by the same limit.

Ruling S3-12 — what the fix must achieve:
1. `POST /_test/import` and `POST /_test/reset` accept bodies far beyond 8 MiB: a limit sized to the 2 GiB memory budget, at least 256 MiB. Ordinary endpoints may keep a small limit.
2. Capacity target: the service imports its own unchanged export inside the 10 s control-call limit for a state of at least 60000 payments + 60000 requests with a few hundred corrections and several thousand statement snapshots, under `--cpus 2 --memory 2g`; export and reset of that state also inside 10 s. Measure and report the real numbers (export size, export/import/reset seconds, container memory) and the largest state you measured inside the limits. If import validation is the bottleneck, make it linear and cheap, not weaker: invalid states must still give 422 with the destination unchanged.
3. A body over any limit, on any endpoint, is answered with a readable 4xx carrying the §5 error body — never a dropped connection or a reset while the client is still sending. (Read and discard the body up to a hard cap before answering, or otherwise make sure the client receives the response.)
4. Keep the export compact where that is free: the snapshot records are already small; do not copy entries into them.
