STAGE-3 AMENDMENT TO DECISION S3-6 — replaces the S3-6 text in the stage-3 handoff (brief, part 1, and acceptance map). Everything else in that handoff stands.

Specification clauses: stage-3.md "Stable statement pagination": "Unknown token, another user's token, or a token from before reset gives 404 `not_found`. Tokens last until reset. No storage survival across container restarts is required." Stage-1 §10: "Import takes that entire object and atomically replaces the service's state … Existing receipts, tokens and retries must remain valid after import … Reset clears all state, including imported state."

Amended S3-6: responses that page a snapshot return the same `snapshot` token again. Snapshot tokens are part of the service state: `GET /_test/export` includes them and `POST /_test/import` restores them, so a token issued before an export still pages the identical frozen result (same entries, `balance_after`, opening and closing balances, `has_more`) after that export is imported into the same or a fresh container, and only for the user it was issued to. Import is replacement: snapshots that existed only in the destination are dropped. Reset drops all snapshots. Exports from stage 1 and stage 2 carry none. Reason: an import is not a reset, so "tokens last until reset" covers it.

Consequences for the build:
- With S3-7 (a snapshot records resolved parameters against the append-only log, not copied entries) each exported snapshot is a small record: token, user id, resolved `from`/`to`, effective `known_at`, and whatever cut-off you use to pin the view. Make sure the pinned view is reproducible from exported state alone — the cut-off must be expressed in exported data (recorded instants or exported sequence numbers), not in process-local counters that restart at zero.
- Import validation covers snapshot records too: malformed ones → 422 `validation_failed`, destination unchanged, never a 5xx later.
- Keep the number of stored snapshots bounded in memory terms (they are tiny), not by evicting live tokens: a token must keep working until reset.
