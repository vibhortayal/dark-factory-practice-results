== ARCHITECT DECISIONS ON OPEN POINTS (binding unless the specification text contradicts them — if you think one does, tell the Architect with the clause) ==

D-1. A caller who is neither party calling pay / decline / cancel on an existing request gets 403 `forbidden` (the endpoint tables say "not the payer / not the requester → 403").
D-2. Precedence on the five idempotent paths: authentication (401) → operator permission on /settlements (403) → Idempotency-Key present and non-empty (400 `missing_idempotency_key`) → key length ≤ 255 (422) → body parses as a JSON object (400 `malformed_request`) → already-claimed key resolved (same JSON value → 200 replay; different → 409 `idempotency_key_reuse`) → endpoint field validation → resource checks. Keys are recorded only for successful (201) operations, per (user, method, path).
D-3. A body that parses as JSON but is not an object is 400 `malformed_request`.
D-4. Wrong JSON type: `amount` (string, boolean, null, non-integral number), `note` (anything that is not a string, including null) and `visibility` (anything other than "public"/"private") are 422 `validation_failed`. Other fields of the wrong JSON type (`to_handle`, `payer_handle`, `email`, `password`, `display_name`, `participant_handles` not an array) are 400 `malformed_request`. Missing required fields are 422. A string handle that does not match the handle pattern cannot name a user: treat as unknown → 404. In /settlements, batch-shape problems (transfers missing, not an array, 0 or more than 32 entries, an entry that is not an object) are 422 `validation_failed`.
D-5. Precedence within one request: field validation (422) → self-payment / self-request (422) → unknown handle (404) → state checks (409). In /settlements the first entry in input order that has any error decides the response, and all entry errors come before `insufficient_funds`. On pay / decline / cancel: unknown request 404 → wrong caller 403 → status 409 → funds 409.
D-6. `amount` accepts any JSON number with an integral value (1000, 1000.0, 1e3) and is always returned as a plain JSON integer. Make sure your JSON parser does not lose this (and does not accept `true` as 1).
D-7. Every payment object, wherever it is returned (POST /payments, pay, /activity, settlements), has the same key set, including `request_id` and `settlement_id` (null when not applicable).
D-8. Note length is counted in Unicode characters (code points), so 200 emoji are accepted; notes round-trip byte for byte.
